# 技术规格：账号、独立人物档案与长期记忆

## 目标

在 Web 产品层增加账号认证，并将人物档案与长期记忆拆成两个独立数据域：

- `ProfileModule`：账号级人物档案，支持 CRUD、软删除和恢复；
- `MemoryModule`：只保存用户明确要求记住的非档案信息；
- `ContextAssembler`：运行时分别读取两者并组装 Agent 上下文。

`wenjia_agent` 核心不依赖 Web 账号、Cookie 或密码。

## 技术约束

- 后端：FastAPI + Pydantic v2 + SQLAlchemy 2.x + SQLite（沿用 `WENJIA_SESSION_DB_URL`）。
- 前端：React + TypeScript + Ant Design，沿用现有组件和 `fetch` 调用风格。
- 认证：服务端有状态会话，令牌通过 `HttpOnly` Cookie 传输；数据库只保存令牌哈希。
- 密码：Argon2id 哈希；新增 `pwdlib[argon2]` 依赖。
- 所有业务接口强制登录；`user_id` 只从服务端会话解析，不接受请求体身份字段。

## 数据模型

### `wenjia_users`

- `id`、`username_normalized`（唯一）、`username_display`、`password_hash`、`created_at`、`updated_at`、`deleted_at`。

### `wenjia_auth_sessions`

- `id`、`user_id`、`token_hash`（唯一）、`created_at`、`expires_at`、`last_seen_at`、`revoked_at`。

### `wenjia_user_profiles`

- 账号级独立档案表，保留现有出生资料和排盘字段，并包含 `user_id`、`created_at`、`updated_at`、`deleted_at`。
- 账号级档案不以 `session_id` 作为所有权；`source_session_id` 只作来源审计。
- 默认查询过滤 `deleted_at IS NULL`。

旧 `wenjia_profiles` 不属于当前模型；应用不初始化、不读取、不迁移该表。

### `wenjia_memories`

- `kind` 仅允许 `preference`、`goal`、`context`、`correction`、`note`。
- 禁止新写入 `profile` 类型以及出生资料、关系、四柱、五行等档案内容。
- 记忆删除为物理删除；档案删除不触发记忆写操作。

## API 合同

### 认证

- `POST /api/auth/register`：用户名、密码、确认密码（两者必须一致）；成功返回当前用户并设置会话 Cookie。
- `POST /api/auth/login`：用户名、密码；成功返回当前用户并设置会话 Cookie。
- `POST /api/auth/logout`：撤销当前会话并清除 Cookie。
- `GET /api/auth/me`：返回当前用户；未登录返回 `401`。

### 人物档案

- `GET /api/profiles`：返回当前账号有效档案。
- `GET /api/profiles/{profile_id}`：返回当前账号的单个有效档案。
- `POST /api/profiles`：创建账号级档案。
- `PUT /api/profiles/{profile_id}`：修改有效档案。
- `DELETE /api/profiles/{profile_id}`：软删除，重复删除幂等。
- `GET /api/profiles/deleted`：返回当前账号回收站档案。
- `POST /api/profiles/{profile_id}/restore`：恢复软删除档案。
- 旧的 session 档案路径已移除，档案只使用账号级接口。

### 长期记忆

- `GET /api/memories`：只按当前登录账号查询。
- `POST /api/memories`、`PUT /api/memories/{memory_id}`：创建/修改非档案记忆，明确拒绝 `kind=profile`。
- `DELETE /api/memories/{memory_id}`：物理删除并按账号归属校验。

## 上下文规则

聊天请求携带 `profile_ids`（可选）和会话标识。服务端：

1. 认证用户从会话解析 `user_id`；没有匿名或游客运行路径。
2. 查询指定账号下未软删除的档案。
3. 独立检索相关长期记忆。
4. 以明确的两个区块传给 Agent，不把档案转写为记忆。
5. 排盘结果保存回档案模块；用户明确“记住”的内容才写入记忆模块。

## 部署规则

- 启动时只创建当前认证、账号档案和长期记忆表。
- 旧游客表、旧 session 档案路由和 `client_id` 数据不兼容；部署前由运维备份或清理。
- 应用不执行历史数据导入、隐式绑定或兼容性迁移。

## 测试策略

- 后端单测：密码哈希、会话 Cookie、档案软删除/恢复、记忆类型校验、迁移幂等。
- API 集成测试：注册/登录/退出、未登录拒绝、资源越权、档案 CRUD、记忆 CRUD。
- 前端测试：认证状态、登录表单、档案加载/保存/软删除、记忆页不展示档案。
- 验证命令：`poetry run pytest`、`poetry run ruff check . --no-cache`、`npm test`、`npm run build`。

## 边界

- 始终执行：服务端归属校验、输入验证、密码哈希、软删除默认过滤、增量测试。
- 需要后续确认：邮箱找回、自动候选记忆、软删除保留期限、社交登录。
- 不做：支付、会员、分享协作、多租户、Agent 核心账号耦合。
